# Stream 控制台与面板需求 v2（2026-09-20）

> **产生原因**：2026-09-20 现场工作流再梳理——明确 UE 面板"只负责启动/配置/兜底"，
> 全局监控必须由**不阻塞的原生常驻窗口**承担，Web 为纯附加。
> **替代**：`Stream面板UI设计规范.md` 中"面板 = 主监控"的定位（面板会冻结，不能当监控）。
> **关联**：`流式面部捕捉管线方案.md`｜`流式引擎核心工序拆解.md`（批次 1-5 已交付）

## 一、核心原则：三个控制台，各司其职

| # | 载体 | 职责 | 是否会被解算阻塞 | 状态 |
|---|---|---|---|---|
| ① | **UE 面板（Stream Tab）** | 配置 · 启动/停止 · 身份绑定确认 · 兜底查阅 | **会**（游戏线程阻塞） | 已有（需收敛） |
| ② | **单任务进度小窗**（UE 控制台 · 原生） | 当前这**一条** take 的进度（Pass/帧/剩余） | 否（**UE 进程内独立线程**） | 已有，已投产 |
| ③ | **全局进度控制台**（UE 控制台 · 原生，新建） | 全部任务列：加载中 / 处理中 / 已完成 —— **实时** | 否（**UE 进程内独立线程**） | ⭐ 本次新增 |
| ④ | Web 仪表盘 | 局域网/手机查看（纯附加） | 否 | 已有（保持附加） |

### 载体纪律（2026-09-20 重申，勿再偏离）

> **②③ 都是 UE 控制台**：与单任务小窗同机制（`FMHSProgressWindow`：
> UE 进程内的 **Win32 原生窗口 + 独立线程 + 自有消息循环 + PostMessage 更新**），
> **不走 Slate、不依赖游戏线程泵** → 解算阻塞 34 分钟、面板冻结期间照常刷新。
>
> **它不是独立进程**：生命周期与 UE 一致（UE 关闭即消失）。
> 唯一跑在 UE 之外的只有 **④ Web 数据端**（原始技术决策：`独立进程只做监控（Web 数据端）`）。

**不可动摇的约束**：
> **没有 Web 也能完成全部工作。** ④ 的缺失只影响"方便"，不影响"能用"。
> 因此 ③ 必须是 UE 内原生控制台（不能是浏览器、也不能依赖外部进程）。

## 二、① UE 面板：收敛为"配置 + 启动 + 兜底"

### 2.0 配置区四项（2026-09-20 用户定名）

| # | 字段 | 类型 | 说明 | job 字段 |
|---|---|---|---|---|
| 1 | **加载路径** | 磁盘 | 监听源（上环节同步素材的目标文件夹） | `inbox` |
| 2 | **身份导入** | UE | ID（ROM）素材导入到工程的资产目录 | `identity_import_root`（新增） |
| 3 | **素材导入** | UE | 表演素材导入到工程的资产目录（按分组建子目录） | `capture_root` |
| 4 | **导出路径** | 磁盘 | FBX 交付输出目录 | `fbx_output_dir` |

```
┌ 配置 ──────────────── E:\Capture\inbox ──┐
│ 加载路径  [E:\Capture\inbox        ] [浏览] │  磁盘·监听源
│ 身份导入  [/Game/CaptureManager/ID ] [浏览] │  UE·ROM 素材落位
│ 素材导入  [/Game/CaptureManager/Auto][浏览] │  UE·表演素材落位
│ 导出路径  [E:\OUT\auto_fbx         ] [浏览] │  磁盘·FBX 交付
│                            [保存为默认]     │
└───────────────────────────────────────────┘
```

**语义分工（避免与身份模块混淆）**：
- **配置区只放 I/O 路径**（四项，纯数据流）——不含身份资产目录、不含制作操作
- **身份资产目录（`/Game/ID`）+ 制作操作**（[导入项目]/[打开编辑器]/[确认完成]）归入下方**身份模块**
  （它是"制作身份"的输入，不是 I/O 配置）

> 待确认（D6）：「身份导入」是否**同时**需要"身份资产目录"（identity 资产放置处）？
> 我的方案：不放配置区——它属于身份模块的制作输入，放在身份区更合语义。

### 2.1 保留（已实现）

- 配置区（可折叠，标题显示加载路径摘要）：四项 I/O + [保存为默认]
- 状态区（**极简**）：状态灯 + 状态词 + [预检] / **[启动监听]**（运行中显示为 [停止监听]）
  - 按钮文案 2026-09-20 定：`启动监听` / `停止监听`（明确"监听"语义，不用泛化的"开始/停止"）
  - **无"下一步"引导行**（2026-09-20 删：步骤条已够明晰，引导行冗余）
- ID 制作区（Semi）：身份资产目录 / [导入项目] / [打开编辑器] / [确认完成]（写入绑定）
- 身份分组区（只读显示绑定关系）
- 日志框（兜底查阅：错误/警告/关键事件）

### 2.2 移除（2026-09-20 最终确认）

- **大数字（今日交付/已同步）→ 删除**（不再保留；计数是监控职责，归 ③）
- **"兜底·段间更新"文案 → 删除**（面板不再解释刷新节奏，因它已不含任何准实时数据）
- 四步卡（ID/Ingest/Solve/Export 累计）→ 移入 ③
- 当前任务行 → 移入 ③
- 异常行（N 条未交付）→ 移入 ③
- 事件流 → 移入 ③（日志框保留兜底）

> **面板状态区最终形态**：`● 运行中` / `○ 未启动` + [预检] [开始]/[停止]。
> 不含任何计数、进度、时间戳——**所有"看数"需求一律引导到 ③**。

### 2.3 二级目录（结论：本期不做）

| 现状 | 结论 |
|---|---|
| 面板为**单层**结构 + 折叠分区（配置/身份/日志），无二级 Tab | **不做二级目录** |

理由：
1. 面板职责已收敛为"配置+启动+绑定"，元素很少——二级导航反而增加点击成本
2. 折叠分区已能承载（配置可折叠、日志可折叠）
3. 触发升级的条件：配置项再增加 ≥4 项（Web 端口/就绪判定/排除名单/解算选项等）时，
   再升级为二级（配置 / 身份 / 日志 三个子页），届时重新评估

### 2.4 身份创建流程（Semi · 完整链路）

```
[现场拍 ROM/ID 素材] ──上环节拷入──▶ inbox/_id/{take}（或名字含 rom）
        │
        ▼ ① 自动：监听发现（就绪判定 3s 稳定）
        ▼ ② 自动：导入为 FootageCaptureData（★ 是，ID 素材自动导入，但不解算）
        │       队列任务 kind=id → done；日志"ID 素材就绪，请在面板完成身份制作"
        ▼ ③ 人工：Identity 编辑器制作身份（导入项目 → 制作 → conform → Prepare）
        │       面板：[导入项目] / [打开编辑器]
        ▼ ④ 人工确认：[确认完成] → 扫描 ID资产目录找到 identity → 写入绑定表（分组→身份）
        ▼ ⑤ 自动：该分组 pending 素材冲刷入队 → 开始解算→导出
```

**关键边界（自动 vs 人工）**：

| 环节 | 是否自动 | 说明 |
|---|---|---|
| ID 素材发现 | ✅ 自动 | 与表演素材同一套监听/就绪判定 |
| **ID 素材导入** | ✅ **自动** | 你问的这点——**是的，监听到就自动导入** |
| 身份资产制作 | ❌ 人工（Semi 定义） | 见下方"自动化阻塞项" |
| 身份绑定 | ⚠️ 半自动 | 人工点 [确认完成]，写入后自动冲刷 |
| 表演素材解算 | ✅ 自动 | 绑定后无需干预 |

**自动化阻塞项（为何身份制作默认人工）**：
- 引擎官方脚本 `create_identity_for_performance.py::create_identity_from_frame()` 可全自动
- 但其 `create_dna_for_identity()` 走 **Mesh to MetaHuman 云端 AutoRig**（需 Epic 账号 + 网络）
- **现场只有挂 IOA 的电脑能联网** → 不能作为默认路径
- 备选：`create_identity_from_dna_file()`（演员已有 DNA 时可**离线**自动创建）

**待办（历史需求，未实现）**：
- 面板配置区增加**「自动身份」开关**（开启后走自动链路；关闭=当前 Semi 人工）
- 前置条件：① 现场可联网（IOA 机器）或 ② 演员有现成 DNA 文件 —— 需你确认哪条成立
- 该开关与身份制作失败回退（自动失败→转人工）一并设计

## 三、② 单任务进度（已有，小改）

原生小窗 + `progress.json`：Pass 权重进度、帧号、已跑时长、剩余预估。
心跳线程 500ms 写 json + 刷窗，**与游戏线程解耦**（设计文档 §5.5）。

### 3.1 素材类型标记（★ 新增）

**问题**：现有导入阶段只显示"导入素材 xxx"，**不区分 ID(ROM) 与表演素材**——
使用者无法判断"这条是在做身份，还是在跑表演"。

**方案**（零结构改动，仅文本前缀）：
- 表演：`导入素材 Anims_ep029`
- 身份：`[ID] 导入素材 0818_face_rom_pm_002`
- 实现：`stream_executor._run_id_task` 调 `progress.monitor_begin_task()` 时名称加 `[ID] ` 前缀
- 解算阶段同理保留原名（身份素材不解算）

### 3.2 阶段行补类型

```
> [ID] 0818_face_rom_pm_002   导入中
[######------] 58%
阶段 导入 ⏵ · （身份素材不解算/不导出）
```

## 四、③ 全局进度控制台（新建 · 核心需求）

### 4.1 形态（UE 控制台 · 与单任务小窗同机制）

- **UE 进程内的原生 Win32 小窗**：复用 `FMHSProgressWindow` 线程模型——
  独立线程 + 自有消息循环 + `PostMessage` 更新，**与 Slate/游戏线程完全解耦**
  → 解算 34 分钟阻塞期间照常刷新（面板冻结它不冻结）
- **生命周期**：随 UE；面板 [开始] 时显示（或创建），[停止] 后**保留常驻**至 UE 退出
  （收工后仍可回看当日战绩）
- 位置：默认右上/副屏角，可拖动；置顶开关
- **不是独立进程**（见 §1 载体纪律）；UE 关闭即随之消失，此为预期行为，不做守护进程

### 4.2 数据来源（单一事实源 = 磁盘）

| 数据 | 来源 | 说明 |
|---|---|---|
| 任务列与状态 | `stream_state.json`（观测层批次4） | 含 delivered/synced/failed/queued/pending_binding/current/eta_seconds |
| 单条实时进度 | `progress.json` | 当前 take 帧进度（可选显示一行） |
| **预期时长** | take 元数据的 MOV 帧数/时长 × 标定系数 | 见 4.4 |
| 已完成交付 | `fbx_output_dir` 目录扫描（或队列 done 计数） | 双源校验（队列为准，目录为佐证） |

读方固定**一次重试**（Windows 共享冲突约定，批次4 已验证零撕裂）。刷新周期 **1s**。

### 4.3 显示区（要求）

```
┌─ Stream 全局进度 · 截至 15:42:07 ──────────── □ ┐
│ 身份带 ⓘ pm/ → ID_pm   ·  ID素材 已导入·待制作身份  │  ← 固定顶部（全局前置条件）
│                                                │
│ 状态 ●运行中 · 队列 12 · 已交付 8 · 失败 0        │
│ 预计追平 18:20（约 2h38m）                       │
│                                                │
│ ▍当前加载（随文件夹加载实时增长）                  │
│   09:12  pm/Anims_ep030      已加载  ·  待解算    │
│   09:15  pm/Anims_ep031      加载中  ·  42%      │
│                                                │
│ ▍处理中                                          │
│   09:02  pm/Anims_ep029      解算中  ·  Pass2/3  │
│                                                │
│ ▍已完成（随 FBX 输出更新 · 仅表演交付）            │
│   08:12  am/Anims_ep001      ✓ 34min  → FBX     │
│   08:47  am/Anims_ep002      ✓ 33min  → FBX     │
│   …（最新在下，自动滚动；超 N 行折叠为摘要）        │
└────────────────────────────────────────────────┘
```

要点：
1. **身份带（固定顶部，★ 新增）**：身份是全局前置条件，不属于任务列。
   显示 `分组 → 身份` + **ID 素材状态**（未就绪 / 导入中 / 已导入·待制作 / 已绑定）
   → 使用者一眼知道"为什么还没开始跑"（ID 未就绪 = 表演素材在 pending 池等待）
2. **当前加载列**：素材一进文件夹即出现（含"加载中=拷贝未稳"态，对应就绪判定），随加载完成转为"待解算"
3. **已完成列**：以 **FBX 真实落盘**为准（不变量 I1），显示耗时（→ 反哺标定）；
   **只含表演交付，ID 素材不进此列**（ID 不是交付物，避免冒充 FBX 交付）
4. 三列随事件实时增长，不依赖面板刷新
5. 异常项（失败）单独置顶显示，红色

### 4.3.1 ID 在三处的统一表示（避免语义混淆）

| 位置 | ID 的表示 |
|---|---|
| ① 面板 | ID 制作区状态行：`ID 状态：未就绪 / 导入中 xxx / 已导入·待制作 / 已绑定 ID_pm` |
| ② 单任务窗 | 任务名带 `[ID] ` 前缀（如 `[ID] 0818_face_rom_pm_002 导入中`） |
| ③ 全局控制台 | **顶部身份带**（不进三列）+ ID 素材状态文案 |
| ④ Web | 同 ③ 口径 |

### 4.4 预期时长 = MOV 时长 → 解算时长（★ 新增能力）

```
单条预期 = 导入耗时 + 解算耗时
  解算耗时 = 帧数 × 标定系数 k（秒/帧）
  k 初值：批次3 实测 1301s / 2351帧 ≈ 0.553 s/帧（i7-10700 + Preview 之外的 AdditionalTweakers）
  k 在线标定：每完成一条，用实际 (耗时 / 帧数) 做滑动平均（最近 5 条），随机器/素材自适应
帧数来源优先级：
  1) 已导入 CD 的帧数（UE 侧，最准）
  2) take.json 元数据
  3) MOV 容器解析（fallback，成本高，仅前两路缺失时用）
```

追平时刻 = now + Σ(待处理条预期) + 当前条剩余。与批次4 的 `eta_seconds` 合并为同一口径（本字段升级为帧数标定版）。

### 4.5 交互（最小）

- 置顶开关、关闭（关闭不终止流程——仅隐藏窗口，可从面板重新拉起）
- 双击已完成行 → 打开该 FBX 所在文件夹（可达性：做完能拿到结果）
- 无编辑类交互（保持只读，避免第二事实源）

## 七、决策点（需你拍板）

| # | 问题 | 建议 |
|---|---|---|
| **D1** | 全局控制台与单任务小窗：**两个独立窗口**还是合并为一个（上/下分区）？ | 建议**两窗**：职责/刷新频率/生命周期不同（单任务随段开合，全局常驻） |
| **D2** | [停止] 后全局控制台：关闭 / 保留常驻（下次 [开始] 复用）？ | 保留常驻（收工后仍可看当日战绩），关闭按钮仅隐藏 |

| **D5** | 全局控制台是否需要**多机集中**（一台机器看所有工位）？ | 本期不做（需服务端）；Web 已可多端查看，够用 |
