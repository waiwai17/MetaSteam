# Stream Tab · UI 设计规范

> **基线**：2026-09-18（v1 定稿）
> **产生方式**：多轮"使用者工作流走查"迭代 + 从已投产的**深度 Tab** 提取被验证的设计
> **关联**：`流式面部捕捉管线方案.md`（功能与架构）｜`MetaHumanSolver_项目文档.md`（实测记录）
> **状态**：设计定稿，实施中（UI 骨架先行，引擎层数据随 S2/S3 接入）

---

## 一、设计原则

### 1.1 三条直觉原则

| 原则 | 内容 |
|---|---|
| **Next Action** | 使用者永远不该想"下一步干嘛"——当前步要可见、可点 |
| **状态诚实** | 没接线的写"未接入"，没做的不能显示"完成"；不自动进位 |
| **可达性** | 做完能拿到结果（打开输出文件夹 / 定位 FBX / 看到清单） |

### 1.2 美观规范（2026-09-18 确立，所有 UI 遵循）

```
色彩语义（不靠符号，靠颜色）
   蓝 = 运行中 / 进行中      绿 = 完成 / 正常
   红 = 错误 / 失败          灰 = 未启动 / 未接入 / 次要

排版层级
   L1 状态词   10pt SemiBold + 颜色
   L2 大数字   24pt SemiBold（视觉焦点）
   L3 标签     9pt  Regular 灰
   L4 正文     10pt Regular

按钮文案
   统一 2-4 字标准动词，无 emoji、无口语
   ✓ 浏览 / 开始 / 停止 / 预检 / 制作身份 / 确认完成 / 重置 /
     打开输出 / 打开清单 / 改绑 / 重跑 / 跳过
   ✗ "⚡去制作" 这类口语 + 符号（已废弃）

符号
   全面板最多保留 ⟲（重置）、▾（展开）两个功能性图标
   完成态用**颜色**（绿）表达，不用 ✓ / ⚡ / ⚠ 等装饰符号
```

### 1.3 技术约束：段间更新 → 快照语义

| 场景 | 面板能否更新 | 机制 |
|---|---|---|
| 解算阻塞中（约 34 分钟） | ❌ 完全不能 | 同步阻塞 → 游戏线程单帧无限延长 → Slate Tick / 渲染 / 消息泵全停（§5.5 已记录） |
| 解算完一条（段间） | ✅ 更新一次 | `Exec` 返回后游戏线程空出，`[MHS_*]` 日志 → `HandleMHLogLine` 驱动刷新（**现有机制，零新增**） |

**UI 必须匹配这个能力**：
- 动态字段一律**"截至 HH:MM"** 快照语义，且时间戳**贴身**放在数值旁
- **不放进度条 / 动画**等暗示实时的元素（34 分钟不动会让人以为卡死）
- 明确告知刷新节奏，并把实时需求引导到旁路（原生小窗 / S5 Web 仪表盘）

## 二、信息分层

| 层 | 内容 | 出现时机 |
|---|---|---|
| **L1 常态**（3 秒扫完） | 状态、今日进度大数字、当前任务、四步卡、身份分组 | 常驻 |
| **L2 异常** | 失败项、未交付项、ID 待办 | **仅出问题时出现**，平时不占空间 |
| **L3 按需** | 配置、事件、清单 | 折叠，点开才看 |

## 三、主界面

```
┌────────────────────────────────────────────┐
│  ● 运行中                    [预检] [停止]   │  L1 状态 + 动作
│                                            │
│            28 / 30                         │  L2 大数字（焦点）
│        今日交付 · 已同步                     │  L3 标签
│                                            │
│  Anims_ep013 解算中 · 截至 09:02             │  当前 + 时间戳贴身
│                                            │
│  ┌────────┬────────┬────────┬────────┐     │
│  │   ID   │ Ingest │  Solve │ Export │     │  四步卡
│  │   2    │   30   │   29   │   28   │     │  （统一"累计通过数"）
│  └────────┴────────┴────────┴────────┘     │
│                                            │
│  身份分组                                   │  显式绑定（自深度Tab）
│   am/  →  ID_am   （14:02 止）      [改绑]   │
│   pm/  →  ID_pm   （当前）          [改绑]   │
│                                            │
│  配置 ▾      事件 ▾      打开清单            │  L3 入口
└────────────────────────────────────────────┘
```

### 3.1 四步卡语义（统一口径）

**必须是"各阶段累计通过数"**（单调递增），不得混用"待处理/进行中/已完成"三种语义：

```
ID 2（身份就绪数） → Ingest 30（已导入） → Solve 29（已解算） → Export 28（已导出）
```
递减链条本身就是流水线状态，无需解释。

### 3.2 身份分组区（核心设计）

- 按**目录分组**（`am/`、`pm/`），每组显式绑定一个身份
- 显示生效时段 + 当前组
- `[改绑]` 可覆盖（解决"某条归错"）
- **事件流每条也带组标识**，绑定关系对每条可见（不只是全局"活跃身份"）

### 3.3 状态变体

| 状态 | 呈现 |
|---|---|
| 未启动 | `○ 未启动` + `[开始]` + 大数字 `0 / 0` + `等待素材…` |
| 运行中 | `● 运行中` + `[预检] [停止]` + 当前任务行 |
| 异常 | 追加红色行：`2 条未交付 · Anims_ep009 失败 · [重跑] [跳过]` |
| ID 待办 | ID 卡为 `0` 且可点，点击展开"ID 制作"三步区 |

## 四、配置面板

```
配置 ▾
─────────────────────────────────
输入 / 输出
  热文件夹  [E:\Capture\inbox  ] [浏览]  ✓
  输出路径  [E:\OUT\auto_fbx   ] [浏览]  ✓  [打开]
─────────────────────────────────
身份
  ID资产目录 [/Game/IDs        ] [浏览]  ✓
  活跃身份    ID_pm            [切换]
─────────────────────────────────
高级 ▾
  导入路径   [/Game/CaptureManager/Auto]
  排除素材   [ROM / 0818_face_rom_*]
  解算选项   ☑ 不含舌头与音频
  就绪判定   ● 标记文件 .done   ○ 静默期
─────────────────────────────────
[保存为默认]
```

要点：
1. **分组**：输入/输出（使用者关心）在上，UE 内部路径收进高级
2. **即时校验**：路径框旁 `✓` 绿 / `!` 红
3. **`[保存为默认]`**：下次开机自动回填（解决"每次重填"）
4. 生产默认（排除名单、不含舌头与音频）**继承自深度 Tab**，高级里可改

## 五、事件面板

```
事件                          [全部▾]
────────────────────────────────────
09:02  交付  Anims_ep012  ✓  am       ← 最新在顶部
08:58  解算  Anims_ep013  ⏵  am
08:24  导入  Anims_ep014  ✓  am

────────────────────────────────────
```

要点：
1. **最新在顶部**（不用滚到底——段间更新场景的最优解）
2. **筛选**：全部 / 失败 / 待处理
3. **就地操作**：失败项 `[重跑] [跳过]`（依赖 S2 重跑 API）
4. **带组列**（am/pm）：与身份分组呼应

## 六、清单面板 ⭐ 对账视图

```
交付清单  09-18                    [打开文件夹]
──────────────────────────────────────────────
已拍 30 · 交付 28 · 失败 1 · 待处理 1
[全部] [失败▾] [待处理] [未交付]
──────────────────────────────────────────────
状态  名称            时间    耗时    组
✓    Anims_ep001     09:12   34min   am
✓    Anims_ep002     09:47   33min   am
✗    Anims_ep009     11:20   —       am   媒体缺失  [重跑]
⏵    Anims_ep030     18:04   —       pm   待处理
──────────────────────────────────────────────
```

要点：
1. **汇总在顶部**：已拍 / 交付 / 失败 / 待处理——**对账一眼完成**
2. **"未交付"筛选**：直接列出缺的条目（收工核对核心需求）
3. **可达**：`[打开文件夹]`、每条可定位 FBX
4. **流式实时更新**：每完成一条追加一行，不能等批处理结束才生成

### 事件 vs 清单（同源两视图）

| | 事件 | 清单 |
|---|---|---|
| 视角 | **时间**（发生了什么） | **对象**（每条什么状态） |
| 何时看 | 运行时 | 收工 / 对账 |
| 排序 | 时间倒序 | 名称 / 状态 |

二者是**同一份状态的两个视图**，不是两套数据。

## 七、Manual 模式

**语义：面板驱动每一步的真实执行**，不是"点一下算完成"。

```
│  ┌────────┬────────┬────────┬────────┐
│  │   ID   │ Ingest │  Solve │ Export │
│  │   0    │   0    │   0    │   0    │
│  └────────┴────────┴────────┴────────┘
│  [制作身份] [导入] [解算灰] [导出灰]     ← 仅当前步可点（严格顺序）
│  [确认完成]                              ← 真实确认后才进位
```

要点：
1. **不自动进位**——点击步骤只"发起"，`[确认完成]` 才推进（① ② 先接，③ ④ 随 S2）
2. **粒度可选**：解算允许"解一条 / 全解"（避免"点一下全跑"失去可控性）
3. **进度由就绪判据推导**，而非内存计数器（解决重启丢失 / 不能回退 / 状态不一致）

| 步骤 | 就绪判据 |
|---|---|
| ID | identity 资产存在且 `can_process()` |
| Ingest | CD 资产存在且媒体路径有效 |
| Solve | Performance 存在且 `can_export_animation()` |
| Export | FBX 真实落盘 |

## 八、继承自深度 Tab 的经验（已投产验证）

| 旧系统设计 | 价值 | Stream 吸收方式 |
|---|---|---|
| **任务行 = 显式绑定** | 一行就是一个"身份↔素材"绑定单元，上下午问题根本不存在 | → **身份分组区**：显式绑定 + 可改绑 + 每条可见 |
| **[一键预检] 独立** | 使用者肌肉记忆：先预检再开跑 | → **[预检] 独立按钮**（不塞进开始监听） |
| **排除名单** | ROM 会被误当表演素材 | → 高级区，继承默认 |
| **生产默认勾选** | "不含舌头与音频"= 团队标准 | → 继承，高级可改 |
| **多组批处理** | 补拍 / 重跑历史素材必需 | → 分组区天然多组；Manual 支持批量补跑 |
| **简单** | 5 字段 + 2 按钮，团队已熟练 | → 常态仅 6 个元素，其余折叠 |

**最重要的发现**：旧系统用**显式绑定**解决身份归属，Stream 初版用**活跃指针隐式推断**是退步。修正为"指针（流式必需）+ 每条绑定可见可覆盖"。
