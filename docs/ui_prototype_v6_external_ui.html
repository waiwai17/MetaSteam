自绘 UI · 原型 v6（配置面板 + 实时部分）

2026-09-22 · 技术栈 C# WPF/WinUI · 独立进程（非 UE 主线程） · 施工蓝图
载体：独立 C# 进程，数据源 100% 是文件（stream_state.json + queue_state.json + progress.json）， 不调用引擎 API、不等待引擎响应 → UE 解算阻塞 34 分钟期间，本窗口照常 1s 刷新、可点可切（根治 V5 面板冻结）。
两模块：① 配置面板（可写：路径/身份绑定 + 引擎进程控制）｜② 实时部分（只读：状态/进度/列表/事件）。
引擎三态：运行中 / 暂停中（完成当前条后退出）/ 已暂停；继续 = 再次启动（队列保留，done 不重跑）。 暂停 = 写 stop.flag + stop.intent → 不重启； 崩溃（无 intent）→ watchdog 自动重启续跑——两者靠 intent 区分。
与 V5 的关系：V5 的「UE Slate 面板 + conhost 控制台」合并为单一自绘窗口；conhost 的鼠标限制消失 → T/O 快捷键降级取消，恢复鼠标点击（打开输出目录 = 点按钮）。
工程来源：GUI 从内置模板工程新建（复制目录，不含现场编译）→ 用户无需手选 .uproject； 模板内含插件（预编译）、MetaHuman 骨架、目录约定（`_id/` · `{组}/`）、空绑定表。 状态 JSON 与资产都随工程走，切换工程 = 切换整套状态。
文案纪律（重要）：界面上只留状态与动作；原理/语义一律收进 ⓘ 悬浮提示，不常驻—— 解释越多理解成本越高、越显复杂。

不冻结的验收方法：① 解算进行中（UE 主线程阻塞 34 分钟）→ 本窗口每秒走动、可点可切； ② 人为挂起引擎进程 → UI 仍可操作并显示「底层无响应」；③ 删除/损坏状态文件 → 显示「等待数据」且不崩溃。

暂停/继续的验收方法：
① 空闲时点暂停 → 引擎与监控立即退出，UI 转为「已暂停」；
② 解算中点暂停 → UI 显示「暂停中 · 剩余约 X 分钟」（不得看起来像没响应），当前条跑完+导出后自动退出；
③ 点「启动/继续」→ 从队列 pending 处继续，已 done 的不重跑（幂等）；
④ 暂停期间投放新素材 → 留在热文件夹，恢复后被发现处理；
⑤ 崩溃（kill，无 intent）→ UI 显示「watchdog 重启中（第 N 次）」，恢复后断点续跑；
⑥ 已 failed 的任务不自动重试，需放回素材触发复活——UI 明示。

模板新建的验收方法：
① 点「新建」→ 复制模板工程完成，状态 JSON 目录与目录约定（`_id/` `{组}/`）已就位；
② 整个过程不要求选择 .uproject、不触发编译；
③ 新工程启动后 doctor 预检通过（编辑器/工程/热文件夹/引导脚本均存在）；
④ 新工程中做身份 → 绑定 → 跑通一条（与既有工程行为一致）。
